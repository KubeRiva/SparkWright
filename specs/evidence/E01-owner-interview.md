## Context

The founder builds several AI-assisted side projects in parallel (an AI chess
tutor, an open-source OMS, a video pipeline) alongside a full-time enterprise
architecture role. He reviewed Google's Elephant-Goldfish Model (EGM) and asked
for a better concept to release as open source.

## Statements (paraphrased from the founder)

- **Q1.** Today he plans in one AI tool, builds in another, and copies reviews
  back and forth by hand between them. He wants the plan → build → review →
  fix loop to run without manual copy-paste.
- **Q2.** He wants specs created and reviewed at multiple levels, not a single
  flat design doc, and the process extended all the way into the build.
- **Q3.** He wants it released as an open-source project under its own name and
  vocabulary, not as a variant of EGM.
- **Q4.** He wants it to be state of the art: research-backed verification,
  not just more review prompts.
- **Q5.** He wants an option to run user interviews to come up with specs.
- **Q6.** He wants it platform agnostic: not tied to one coding agent.
- **Q7.** He prefers hands-off workflows because his time is limited by a
  full-time role.

## Themes

| Theme | Statements |
| --- | --- |
| Remove manual hand-offs between plan, build and review | Q1, Q7 |
| Multi-level specs carried through to code | Q2 |
| Independent identity and open release | Q3 |
| Verification that can be measured, not just opinion | Q4 |
| Specs grounded in what users say | Q5 |
| Portability across tools and models | Q6 |
